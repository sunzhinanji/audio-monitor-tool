音频监控工具 - 开发记录

> 一个 Windows 平台下的实时音频进程监控工具，能够检测系统中正在使用音频通道的程序，并支持进程追踪、音量监测、快速定位和结束进程。


一、项目起源

1.1 背景

在日常使用电脑时，经常遇到以下场景：

- 某个程序在后台播放声音，但找不到是哪个程序
- 浏览器标签页众多，不知道哪个标签页在发声
- 需要快速结束某个发声程序，但任务管理器里进程太多难以定位

市面上现有的音频监控工具要么功能单一，要么依赖复杂的音频 API。我决定自己开发一个轻量、高效、易用的音频监控工具。

1.2 技术挑战

开发过程中遇到的核心挑战是：Windows 音频 API 被音频驱动拦截。

我的系统安装了 FXSound 音频增强软件，它会拦截 Core Audio API 的调用，导致 pycaw 等库无法正常获取音频会话信息。这迫使我寻找更底层的检测方案。


二、技术选型与演进

2.1 方案探索历程

阶段一：窗口标题关键词检测

原理：遍历所有窗口标题，匹配 "抖音"、"音乐" 等关键词

结果：误报率高，无法检测无窗口进程（如后台播放的音乐播放器）

结论：放弃


阶段二：Core Audio API（pycaw）

原理：使用 pycaw 库获取音频会话

结果：被 FXSound 驱动拦截，无法获取音频设备

结论：放弃


阶段三：Windows 内核句柄枚举

原理：使用 NtQuerySystemInformation API 枚举系统所有句柄，匹配音频设备对象类型

结果：成功检测到音频进程，不受音频驱动影响

结论：采用


阶段四：三重检测增强

在句柄检测基础上，增加：
- 音频设备文件检测（\.wave, \.midi, \.mixer, \.ks）
- 音频 DLL 加载检测（audioses.dll, audioeng.dll, wdmaud.drv）

结果：检测准确率大幅提升

结论：采用（1.0 版本）


阶段五：NAudio COM 集成

原理：通过 C# 编写 Program.exe，使用 NAudio 库的 COM 接口获取音频会话

新增能力：获取每个进程的实时音量峰值（dB）

结果：更精确的检测，支持音量显示

结论：采用（1.3 版本起）

2.2 最终技术方案

语言：Python 3.8+

GUI框架：PySide6（Qt for Python）

音频检测：NAudio COM（C# Program.exe）+ 句柄扫描回退

进程管理：psutil

音量计算：math.log10（将峰值转换为 dB）


三、版本演进

v1.0 —— 基础功能

发布日期：2026年8月

核心功能：

- 三重音频检测（句柄 + 设备文件 + DLL）
- 区分用户进程和系统进程
- 双击进程复制 PID 并自动打开任务管理器
- 像素点扫描动画
- 导出日志 / 清空历史
- 快速退出机制（<= 0.5 秒）

技术亮点：

- 使用 NtQuerySystemInformation 内核 API
- 多步骤扫描均检查退出信号，确保快速响应


v1.1 —— 进程追踪

发布日期：2026年8月

新增功能：

- 进程状态追踪（首次出现 / 持续活跃 / 消失）
- 进程持续时间统计
- 间隔记录（记录进程消失到重新出现的间隔）
- 定位进程物理文件（双击灰色进程）
- 颜色标识：
  - 白色：活跃进程
  - 灰色：已消失进程
  - 橙色：恢复进程（曾消失又出现）


v1.2 —— 立体声混音方案（已放弃）

发布日期：2026年8月

尝试方向：使用 sounddevice + 立体声混音检测声音

失败原因：

- 依赖立体声混音设备，很多系统默认未启用
- 无法区分具体是哪个进程在发声
- 只能检测是否有声音，无法定位进程

结论：放弃，继续使用内核检测方案


v1.3 —— NAudio COM 集成

发布日期：2026年8月

重大更新：

- 通过 C# 编写 Program.exe，使用 NAudio 库获取音频会话
- 新增音量检测功能，显示每个进程的实时音量（dB）
- 扫描间隔优化至约 550ms
- 保留句柄扫描作为回退方案

这一版本标志着检测引擎的重大升级，从"检测到进程"升级为"检测到进程及其音量"。


v1.3.2 —— 扫描间隔优化

改进：

- 读取超时从 3 秒缩短至 0.5 秒
- 扫描间隔从 1.5 秒缩短至约 0.55 秒
- 更灵敏的实时响应


v1.3.3 —— 持续时间归零修复

问题：持续时间从工具启动就开始计时，无论进程是否发声

修复：持续时间改为根据音量计时，进程静音时归零


v1.3.4 —— 颜色规则重构

新的颜色规则（按优先级）：

1. 灰色：进程已消失/退出
2. 橙色：有间隔记录且进程未消失（无论是否静音）
3. 白色：静音（无间隔记录）
4. 绿色：首次发声

同时移除了右上角"最后扫描"显示，精简历史记录。


v1.3.4.1 —— 恢复橙色修复

问题：静音/暂停后恢复播放时，进程没有被标记为橙色

修复：新增 last_silent_time 记录静音开始时间，恢复时计算间隔并触发橙色


v1.3.5 —— 最后消失修复 + 扫描文字优化

问题1：进程暂停时错误地记录了"最后消失"时间

修复：last_disappear_time 只在进程真正退出时记录

问题2："扫描中..."文字闪动

修复：扫描完成后延迟 300ms 清除文字


v1.3.6 —— 间隔记录修复

问题：间隔记录为空，暂停再播放不触发橙色

原因：静音时没有记录时间，恢复时没有时间可计算

修复：新增 last_silent_time 和 last_disappear_time 两个独立变量，分别记录静音和退出


v1.3.7 —— 双击响应修复

问题：双击进程有时失效，需要多次双击

原因：itemDoubleClicked 信号在快速操作时可能丢失

修复：重写 mouseDoubleClickEvent，直接捕获鼠标双击事件


四、功能完整清单

4.1 检测能力

- 实时检测正在使用音频的进程
- 区分用户进程和系统进程
- 显示每个进程的实时音量（dB）
- 支持 NAudio COM 和内核句柄双重检测

4.2 进程管理

- 双击白色/绿色/橙色进程：复制 PID 并打开任务管理器
- 双击灰色进程：定位进程对应的物理文件
- 结束选中的进程（taskkill /F）

4.3 状态追踪

- 进程首次出现时间
- 当前连续发声时长（静音归零）
- 进程消失时间
- 间隔记录（静音/暂停到恢复的时间，以顿号分隔）

4.4 颜色标识

- 白色：静音（存活但无声音）
- 绿色：首次发声
- 橙色：恢复（有间隔记录）
- 灰色：消失（进程已退出）

4.5 辅助功能

- 像素点扫描动画
- 历史记录自动滚动
- 导出日志为 txt 文件
- 暂停/继续监控
- 快速退出（<= 0.5 秒）


五、使用环境

5.1 系统要求

- 操作系统：Windows 10 / Windows 11（64位）
- Python：3.8 或更高版本
- 权限：建议以管理员身份运行

5.2 依赖库

PySide6 >= 6.5.0
psutil >= 5.9.0
pywin32 >= 306
NAudio（C# 项目，已编译为 exe）
